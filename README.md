# focusdemo

BORUIX 的**对抗性验收程序**：验证焦点切换操作被权限门禁拦住。

[English](README.en.md)

## 测什么

切换终端焦点是一个受权限控制的操作。本程序以**普通用户身份**（不是系统身份）被拉起，然后**故意
尝试**执行该操作，**期望被内核拒绝**。

| 观察到的结果 | 判定 |
| --- | --- |
| 被拒绝，错误为"权限不足" | **PASS**——门禁存在且真的拦得住 |
| 被拒绝，但错误是别的（如"参数无效"） | **FAIL**——说明门禁没有先判身份，先解析了参数 |
| **居然成功了** | **FAIL（最严重）**——门禁被绕过，任何程序都能劫持终端 |

## 注意：这是一个期望失败的程序

**它的"成功"是被拒绝。** 如果看到它返回 `0` 并打印 `PASS: denied with EACCES`，那正是预期结果。

反过来，如果它打印 `FAIL: FOCUS_SET succeeded`，那才是真正的严重问题。

## 为什么错误码也要核对

只判"被拒绝"是不够的。**先判权限、后解析参数**是有意的顺序：如果实现反过来先解析参数，那么
一个无权限的调用者就能通过不同的错误码**探测某个对象是否存在**。所以本程序要求返回的必须是
"权限不足"，其他错误码一律算失败。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 被"权限不足"拒绝，门禁成立 |
| `1` | **操作意外成功**，门禁被绕过 |
| `2` | 被拒绝，但错误码不对 |
